The v5 pmp and Racket judges authenticate the supplied initial registry against the embedded canonical REG0 before checking theorem steps. Every entry, including its formula and hypothesis list, must equal the corresponding canonical entry. Empty registry and canonical prefixes through 706 entries are accepted. Altered formulas, altered hypotheses and registries longer than 706 entries are rejected.

The canonical data and authentication implementation are unchanged from v4. The Racket module registry-auth-v4.rkt supplies canonical-registry, canonical-registry-entry, canonical-token-entries, authenticated-prefix? and authenticated-token-prefix?. The pmp judge contains its canonical reference as literal program bytes and uses exact parsed integer values for comparison. No reference file is loaded at runtime.

V5 corrects the decimal parser's treatment of leading zeros. Numeric tokens denote exact integers in 0..999999999999. An arbitrary number of leading zero digits does not count against the 12-significant-digit bound. An all-zero token denotes zero. A 13th significant digit is rejected before arithmetic, so native signed 64-bit accumulation does not overflow. The Racket v5 entrypoint uses the same declared integer domain.
