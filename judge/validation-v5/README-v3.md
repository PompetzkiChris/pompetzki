This component contains the exact 254 cases used by the frozen v5 validation receipt, their input hashes and reviewed expectations, a portable runner, a compact table of the preceding 898 executions, and fresh executions through the portable runner. It uses only Python standard libraries. Supply checker executables and judge source paths explicitly.

Run the 136 bot/numeric cases on all three checker routes from a source-package root with:

    python judge/validation-v5/run-validation-v2.py --output fresh-validation --lane fast --native judge-native.exe --interpreter pompetzki.exe --pmp-source judge/judge-v5.pmp --racket-executable racket --racket-source judge/judge-v5.rkt

Use the corresponding native executables on Linux. A standalone Racket checker may be supplied with --racket-standalone instead of --racket-source. The output directory must be new. Arguments are passed directly to child processes, so source, executable, corpus and output paths may contain spaces. No shell or author directory is required.

--lane full selects all 254 cases for native and Racket. The interpreted route defaults to --interpreted-lane fast, retaining the 136 bot/numeric cases. Supply --interpreted-lane full to include the 117 math cases and full replay in interpreted executions. --families narrows the selected families; repeated --case arguments select exact case IDs. --timeout is the per-execution limit in seconds; --jobs controls concurrent checker processes. The runner checks each selected corpus SHA256 before execution.

The families are 78 bot semantic cases, 16 malformed bot inputs, 42 added numeric/authentication cases, 117 released math cases, and one full replay. The math batch contains 78 accepted inputs and 39 rejected mutations. The native math rejection classes are 23 parser, 12 proof-step and four final-statement. Racket recorded 24 parser, 11 proof-step and four final-statement. The differing case math-Q203-77 produced mp: second line is not an implication at theorem37/step9 in both native builds, while Racket reported unexpected step tag i at byte84138. expectations.tsv retains these route-specific classes. Earlier math expectations declared verdict/exit and left class unspecified; class_basis records that review. The full interpreted lane was not previously run, so its class expectations use the native classes and are marked in interpreted_class_basis. The bot and numeric classifications retain their preceding declared expectations.

The failure classifier reports accept, registry, parser, final-statement or proof-step from each checker's recorded output. It is a diagnostic grouping of this corpus. A parser rejection is recorded as parser coverage, including parser-class math mutations. It does not establish a semantic proof rejection.

Every execution records stdout, stderr, exit code, timeout status, input hash, expected and actual verdict/class, and pass status. summary.json and results.tsv give compact actual results. results.json identifies command roles and input files without embedding machine account or author paths. Runtime input filenames and hashes identify the supplied executables and sources. Raw checker outputs are retained alongside those receipts. A manifest hashes every run artifact.

The previous-results.tsv table is a sanitized copy of the preceding actual 898 runs; it is not a new execution. actual-fast-run contains the subsequent 408 executions made by this public driver on Windows native, Racket and the interpreter. The folder's source manifest and SHA256 list identify the complete reviewed component. Finite validation does not establish executable-to-Gallina or compiler correspondence. The frozen source/native 86-file map remains a separate component.
